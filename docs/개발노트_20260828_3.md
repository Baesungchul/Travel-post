# 찍고쓰다 — 4단계(여행 묶기) + 달력·일정

작성 2026-08-28 (저녁). v0.2.0 → **v0.3.0**.
설계안 9장 4단계를 채우고, 사용자 요청으로 **달력·일정**을 새로 넣었다.

---

## 1. 여행 단위 묶기 (설계안 9장 4단계)

`js/trips.js` · `js/plans.js` 신설. `place.tripId` 는 설계안 2장에 이미 자리가 있었다.

- 장소 하나 = 글 하나가 **여전히 기본**이다. 여행은 그 위에 얹는 **선택 묶음**이다.
- 여행을 지워도 장소는 남는다 — 묶음만 푼다.
- 한 장소는 한 여행에만 들어간다. 겹치면 "이 사진이 어느 글에 들어갔지"가 무너진다.

### ☠️ 토큰 함정이 새 얼굴로 다시 나왔다

여행은 맛집 + 관광지 + 카페가 섞인다. 그런데 `{카테고리}` 는 프로필 하나에서 나온다.
프로필 하나로 치환하면 **관광지 이야기가 맛집 글처럼** 나온다 — 현장매니저 v507 과 같은 병이다.

→ 여행 글은 `Trips.tripProfile()` 이 만드는 **중립 프로필('여행')** 로 치환하고,
각 장소의 실제 카테고리는 프롬프트에 **데이터로** 넘긴다(`ai.js` 의 `tripMeta`).
실측으로 확인했다 — 여행 글의 sys 에 '맛집'도 '관광지'도 들어가지 않고, 남은 토큰도 0이다.

### ☠️ 사진 마커도 다시 문제가 됐다

한 여행에 '외관' 태그가 장소마다 하나씩이다. 태그 이름만으로는 어느 가게 외관인지 모른다.
→ 여행 글의 태그는 **'상호 - 태그'** 합성 이름을 쓴다(`Trips.asPlace`).
`site/post.html` 은 태그를 정확히 먼저 맞추므로 **고칠 필요가 없었다.**

`Trips.asPlace()` 로 여행을 '가상 장소'로 만들어 두니, 공유·PC 링크·사진 정렬이
**장소 하나일 때와 똑같은 코드**로 돈다. 분기가 없다.

### 실측으로 잡은 것 — 담는 순서

예전엔 여행에 장소를 담으면 무조건 뒤에 붙었다. 여행은 시간 순서가 곧 글의 흐름이라,
나중에 담은 곳이 앞 이야기로 가버렸다.
→ **방문 시각에 맞는 자리에 끼워 넣는다.** 기존 순서는 다시 정렬하지 않는다
(손으로 ▲▼ 맞춰 둔 것을 덮으면 안 되므로). 전부 맞추고 싶으면 [🕘 시간순 정렬] 버튼.

## 2. 달력 · 일정 (사용자 요청)

설계안 4장에서는 "달력은 없다"였는데, 여행은 **날짜가 뼈대**라 계획을 날짜에 놓고 보는 편이 맞다.

⚠️ 현장매니저 `calendar.js`(3,907줄)를 옮기지 않았다. 작업·호수·팀 공유·월매출이 한 파일에
얽혀 있어 지우는 게 새로 짜는 것보다 오래 걸린다(설계안 7장의 판단 그대로).
**가져온 것은 두 가지뿐**이다:

- 한국 공휴일 표(2024~2028) — 음력 명절·대체공휴일이 들어간 실제 자산
- 표에 없는 해는 양력 고정 공휴일만 쓰는 폴백 규칙

### ⭐ 계획이 기록으로 이어진다 — 이게 이 기능의 전부다

현장매니저의 일정은 '가야 할 작업'이었다. 여기서는 **'가 볼 곳'** 이고,
다녀오면 그 자리에서 기록으로 이어져야 한다.

```
달력에서 ＋일정  →  [📷 방문 시작]  →  계획의 이름·카테고리·날짜를 물려받은 장소가 열림
                                      →  촬영 → 태그 정리 → 글
```

- `plan.placeId` 로 서로 연결된다. **같은 계획을 두 번 눌러도 기록이 갈라지지 않는다**(실측 확인).
- 여행에 속한 계획이면 만들어진 장소가 그 여행에도 자동으로 담긴다.
- 일정을 지워도 이어진 기록은 남는다.

### 화면

탭은 4개 그대로다. 기록 탭의 **보기**를 넷으로 늘렸다: **달력**(기본) / 목록 / 지도 / 여행.
한 칸에 여행 기간 · 일정 · 기록 세 종류의 점이 찍힌다.

⚠️ 달력·여행 보기에서는 카테고리 필터를 **감춘다** — 거기서는 아무 일도 하지 않는데,
동작 안 하는 버튼을 띄우면 사용자가 자기가 잘못 누른 줄 안다.

## 3. 하마터면 조용히 잃을 뻔한 것

스토어를 둘(`trips`, `plans`) 추가하면서 **백업에 넣는 것을 빠뜨릴 뻔했다.**
백업은 실패하지 않고 그냥 그것만 빠진 채로 만들어진다 — 나중에 복구할 때 알게 된다.

→ `tools/check.js` 에 검사를 넣었다. `store.js` 의 스토어 목록을 읽어
`backup.js` · `cloud_backup.js` 가 전부 담는지 확인하고, 빠지면 **실패**로 잡는다.

```
✅ 백업이 스토어 5종을 모두 담음: places, photos, posts, trips, plans
```

백업 형식은 `fmt 1 → 2` 로 올렸다. 옛 백업도 그대로 읽힌다(없는 배열은 빈 배열로 본다).
