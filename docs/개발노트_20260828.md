## 설계안에서 **바꾼 판단 3가지** (검토 바랍니다)

### 1. 사진 비율 — 가로 4:3 고정을 버렸다
현장매니저는 보고서 사진 칸에 맞춰 촬영·첨부를 전부 **가로 4:3 중앙 크롭**했다.
맛집·여행에서 그대로 쓰면 접시 가장자리와 메뉴판 아래가 잘린다.
음식은 정사각/세로가 표준이고 인스타 피드는 4:5다.
→ 카메라에서 **4:5 / 1:1 / 3:4 / 4:3** 중에 고르고(기본 4:5), `image.js` 는 크롭 없이
긴 변만 1600px 로 줄인다.

### 2. 사진을 IndexedDB Blob 으로 저장
현장매니저는 사진을 파일시스템 핸들(FSA / Capacitor FS)에 뒀고, 그래서
'폴더 권한이 풀리면 사진이 안 보이는' 문제를 오래 안고 갔다(`app.js` 의 진단 함수가 그 흔적).
이 앱은 한 장소당 수십 장 규모라 Blob 저장으로 충분하고, 권한 개념이 없어 그 사고가 안 생긴다.
갤러리 내보내기·백업은 별도 경로로 3단계에 붙인다.

### 3. 프록시가 없어도 전체 흐름이 돌아간다
`PROXY_URL` 이 비어 있으면 **"뼈대 초안"** 을 만든다 — 메모·태그로 짠 글 골격에
`(사진: 음식)` 마커까지 들어간다. 화면에 **"AI 글이 아니다"** 라고 붉은 상자로 명시한다.
덕분에 키를 하나도 안 넣고도 촬영 → 태그 → 글 → 공유를 끝까지 시험할 수 있다.

## 실측한 것 (2026-08-28, 헤드리스 크로뮴)

전체 흐름 16개 지점을 통과시켰다: 앱 로드 → 새 장소 → 사진 4장(태그 3종) →
태그 순서 정렬(`외관,음식,음식,메뉴판`) → 글 시트(준비중 채널 2개 비활성) →
뼈대 초안에 `(사진: 음식)` 마커 → 저장 → 글 탭 → 기록 탭 → 설정 탭 →
카테고리 편집 → 지침 기본값 **토큰 전부 치환됨** → 다크 모드 →
카테고리 전환 시 태그·안내 문구가 따라옴(`풍경,안내판,인물,디테일` / "예) … 코스 안이 …").

**고친 버그 1건** — 서비스워커 `controllerchange` 가 첫 설치에도 발생해서
앱을 처음 열 때 화면이 두 번 다시 뜨고 있었다(실측으로 발견). 
페이지 로드 시점에 이미 컨트롤러가 있었을 때만 새로고침하도록 고쳤다(`app.js`).

## 다음에 채울 것 — `www/js/config.js` 한 파일

| 값 | 무엇에 필요 | 메모 |
|---|---|---|
| `FIREBASE` | 로그인·백업·PC 링크 | **새 프로젝트를 새로 판다**(설계안 7장). 현장매니저 프로젝트에 섞지 말 것. `site/post.html` 위쪽 `PROJECT`/`API_KEY` 에도 같은 값을 넣어야 한다 |
| `PROXY_URL` | AI 글 생성 | ⚠️ **인증을 처음부터 붙일 것.** 앱은 Firebase ID 토큰을 `Authorization: Bearer` 로 보낸다(`ai.js` `authHeader`). 서버가 이걸 검사하지 않으면 프록시는 열려 있는 것 |
| `POST_BASE` | PC 링크 | `www/site/post.html` 을 올린 주소 |
| `KAKAO_REST_KEY` | 주변 장소 자동 채움 | ⬜ **무료 쿼터·약관·상업적 이용 조건 확인 전** |

## ⬜ 아직 확인 안 한 것 — 사실처럼 말하지 말 것

설계안 10장 그대로 남아 있다.

- 티스토리·브런치 에디터의 외부 이미지 재업로드 여부 (**네이버만 실측됨**)
  → `ai.js` 의 `tistory` 채널은 `ready:false`, 글 만들기에서 못 고른다
- 스레드·X 의 안드로이드 공유시트 다중 이미지 동작 → `threads` 도 `ready:false`
- 카카오 로컬 API 무료 쿼터·약관·상업적 이용 조건
- 해외 위치 검색 수단
- Play 스토어 카테고리 및 유사 앱 경쟁 상황 (조사 안 함)

실측이 끝나면 `ai.js` 의 `ready:true` 한 글자만 바꾸면 채널이 열린다.

## 남은 단계 (설계안 9장)

- **2단계** — 인스타 공유 실기기 확인, 갤러리 불러오기 EXIF 좌표 파싱, 카테고리 프로필 UI 다듬기
- **3단계** — 로그인·백업·구독(`Subs.gateFeature` 게이트 구조 이식), 지도 보기, 티스토리/스레드(실측 후)
- **4단계** — 여행 단위 묶기(`tripId`), 여러 장소를 한 편으로 합치기

⚠️ 설계안 9장 경고 그대로: **현장매니저가 sw v599까지 만들어 놓고 재빌드·cap sync·hosting 배포가 대기 중이다.**
두 앱을 동시에 미완 상태로 두지 말 것 — 이쪽에 키를 넣기 전에 그쪽을 먼저 닫는 편이 낫다.
