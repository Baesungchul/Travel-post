## 1. Firebase 새 프로젝트 — ⏱ 20분

☠️ **현장매니저 프로젝트에 얹지 마세요.** 실사용자가 쓰고 있고 핵심 자산이 사진입니다.
여기서 규칙 하나 잘못 배포하면 그쪽으로 번집니다.

### 요금제 — 이미 갖고 계신 결제 계정을 그대로 씁니다

Storage 와 Functions 는 무료(Spark) 플랜에서 안 됩니다. 2024년 9월 이후 새 Storage 버킷은
Blaze 를 요구하고, Functions 도 예전부터 Blaze 전용입니다. 이 앱은 둘 다 씁니다.

**그런데 요금제는 프로젝트마다지만, 결제 계정은 계정 단위입니다.**
현장매니저 때 이미 Blaze 로 올려두셨으니 **카드를 새로 등록할 일은 없습니다.**
새 프로젝트에서 업그레이드를 누르고 **기존 결제 계정을 고르기만** 하면 됩니다.
하나의 결제 계정에 여러 Firebase 프로젝트를 달 수 있습니다.

무료 한도는 그대로 있습니다(Firestore 하루 읽기 5만·쓰기 2만·저장 1GiB, Auth 월 5만 명).

다만 **Storage 는 서울(asia-northeast3) 리전에 "항상 무료"가 없습니다** —
무료 5GB 는 미국 리전(us-central1 등)에만 적용됩니다. 서울에 두면 첫 바이트부터 과금인데,
요율이 GB당 월 약 $0.02 라 사진 1GB 를 두어도 월 30원 수준입니다.

> **판단하실 것:** Storage 를 서울에 둘지, 미국에 둬서 5GB 무료를 받을지.
> 서울이면 업로드가 빠르고, 미국이면 공짜인 대신 사진 올릴 때 조금 느립니다.
> Firestore(기록)는 서울로 두고 Storage 만 미국에 둬도 됩니다 — 서로 상관없습니다.

⚠️ **예산 알림은 하나 더 만드시는 게 좋습니다.** 두 앱이 같은 결제 계정을 쓰게 되므로,
지금 걸려 있는 알림이 계정 전체 기준이면 현장매니저 요금과 섞여 보입니다.
Google Cloud 콘솔 → 결제 → 예산 및 알림 → 예산 만들기에서 **범위(Scope)의 프로젝트를
새 프로젝트 하나로 지정**하면 찍고쓰다 요금만 따로 볼 수 있습니다.
(한 결제 계정에 예산을 여러 개 둘 수 있습니다)

### 절차

1. https://console.firebase.google.com → **프로젝트 추가** (이름 예: `travel-post`)
   - Google 애널리틱스는 **꺼도 됩니다** (지금 안 씁니다)
   - 만든 뒤 **Blaze 로 업그레이드** → 기존 결제 계정 선택 (카드 재등록 없음)
2. **Authentication** → 시작하기 → **이메일/비밀번호** 사용 설정
3. **Firestore Database** → 만들기 → 위치 **asia-northeast3 (서울)** → 프로덕션 모드로 시작
4. **Storage** → 시작하기 → 위 판단대로 리전 선택
5. 프로젝트 설정(⚙️) → **내 앱 → 웹(`</>`)** 추가
   - 앱 닉네임 아무거나, **Firebase 호스팅 설정 체크는 하지 않아도 됩니다**(나중에 CLI 로 합니다)
   - 나오는 `firebaseConfig` 를 통째로 복사

### ❓ 안드로이드 앱은 등록 안 해도 되나요 — 네, 지금은 안 해도 됩니다

이 앱은 **웹 코드가 WebView 안에서 도는 구조**(Capacitor)라, 쓰는 것은 웹 SDK 입니다.
그래서 **웹(`</>`) 앱 등록만 하면 되고**, 안드로이드 앱 등록도 `google-services.json` 도
지금은 필요 없습니다. **안드로이드 스튜디오는 6번에서 처음 씁니다.**

나중에 이것들을 넣을 때 그때 안드로이드 앱을 등록하면 됩니다:

| 나중에 넣을 것 | 그때 필요한 것 |
|---|---|
| 푸시 알림(FCM) | 안드로이드 앱 등록 + `google-services.json` |
| 구글 로그인(네이티브) | 위 + SHA-1 / SHA-256 지문 등록 |
| Crashlytics · Analytics | 위와 같음 |

### 넣기 — 손으로 두 번 옮기지 마세요

Firebase 값은 **두 곳에** 들어갑니다(`config.js` 와 `site/post.html`).
한쪽만 바뀌면 앱은 되는데 PC 링크 페이지만 조용히 안 열려서, 원인 찾기가 어렵습니다.
그래서 넣어주는 도구를 만들어 뒀습니다.

```
1) 복사한 firebaseConfig 를 C:\travel-post\keys.txt 에 붙여넣고 저장
2) node tools/setkeys.js keys.txt
```

원본은 `.bak` 으로 남고, 끝나면 아직 안 채운 값이 뭔지 알려줍니다.
다 하셨으면 `keys.txt` 는 지우셔도 됩니다.

> 이 값들은 공개돼도 되는 식별자입니다. 보안은 `firestore.rules` / `storage.rules` 가 합니다.

## 2. AI 프록시 — ⏱ 30분 · 가장 중요

☠️ **인증을 반드시 붙이세요.** 현장매니저는 프록시가 인증 없이 열려 있고 주소가 APK 안에
그대로 있습니다. 주소만 알면 남이 사장님 API 요금을 쓸 수 있는 구조입니다.
이 앱은 처음부터 로그인 토큰을 보내게 짜뒀습니다 — **서버가 그걸 검사만 하면 됩니다.**

앱이 보내는 것:
```
POST <PROXY_URL>
Authorization: Bearer <Firebase ID 토큰>
{ model, max_tokens, system, messages }
```

서버가 할 일:
1. `Authorization` 헤더의 Firebase ID 토큰을 검증 (Firebase Admin SDK `verifyIdToken`)
2. 통과하면 `https://api.anthropic.com/v1/messages` 로 그대로 넘기고 응답을 돌려줌
3. `ANTHROPIC_API_KEY` 는 **서버 환경변수에만** 둔다

Cloudflare Workers 든 Vercel 이든 상관없습니다. 현장매니저의 `vercel-proxy` 를
복사해 쓰셔도 되는데, **1번(토큰 검증)을 반드시 추가**하세요.
주소가 나오면 `www/js/config.js` 의 `PROXY_URL` 에 넣습니다.

> 원하시면 인증이 붙은 프록시 코드도 짜드리겠습니다 — 말씀만 주세요.

## 5. 배포 — ⏱ 10분

키를 다 넣은 뒤:

```
cd C:\travel-post
npm run check                 # 미설정 값이 남았는지 먼저 확인
npx firebase login
npx firebase use --add        # 1번에서 만든 프로젝트 선택
npx firebase deploy --only firestore:rules,storage,functions,hosting
```

배포되면 `https://<프로젝트>.web.app/post.html` 이 PC 링크 페이지 주소입니다.
그 주소를 `config.js` 의 `POST_BASE` 에 넣고 앱을 다시 배포하세요.

☠️ **`functions` 를 빼먹지 마세요.**
- `cleanupSnsPosts` — PC 링크 사진을 24시간 뒤 실제로 지웁니다. 없으면 사진이 서버에 계속 쌓입니다.
- `deleteUserData` — 계정 삭제 시 Storage 파일을 지웁니다. **이게 없으면 Play 심사에서 문제가 됩니다.**

## 8. 제가 못 하는 실측 — 실기기 필요

이게 끝나면 채널 두 개가 더 열립니다. `www/js/ai.js` 에서 `ready:false` 를 `true` 로만 바꾸면 됩니다.

| 확인할 것 | 방법 | 결과를 넣을 곳 |
|---|---|---|
| 티스토리·브런치가 붙여넣은 **외부 이미지를 자기 서버로 가져가는가** | PC 링크를 만들어 티스토리 글쓰기에 Ctrl+V → 발행 후 이미지 주소가 `tistory` 로 바뀌는지 확인 | `ai.js` 의 `tistory.ready` |
| 스레드·X 가 **공유시트로 사진 여러 장**을 받는가 | 폰에서 사진 3장 공유 → 스레드 선택 | `ai.js` 의 `threads.ready` |
| 인스타 공유가 실기기에서 잘 되는가 | 앱 빌드 후 사진 여러 장 공유 | 이미 `ready:true` — 확인만 |

> 네이버 블로그는 현장매니저에서 **이미 실측 완료**입니다(2026-08-27, `postfiles.pstatic.net` 확인).
> 다시 조사하지 마세요.
