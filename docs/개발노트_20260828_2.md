## 판단 3가지

### 1. 로그인보다 **로컬 백업**을 먼저 만들었다
이 앱의 핵심 자산은 사진이고, 사진은 지금 이 기기 안에만 있다.
Firebase 키가 아직 없다고 유실 대비를 미룰 이유가 없다.
`js/backup.js` 는 서버 없이 완결된다 — 사진·기록·카테고리·지침을 **ZIP 하나**로 내보내고 되돌린다.
클라우드 백업은 그 위에 같은 구조로 얹었다.

### 2. 복구는 **합치기(비파괴)** 가 기본이다
현장매니저에서 배운 것: 덮어쓰기가 기본이면 실수 한 번에 전부 잃는다.
- 합치기 — 같은 id 가 이미 있으면 건드리지 않는다. 없는 것만 채운다.
- 덮어쓰기 — 사용자가 명시적으로 고를 때만. 그때도 **지우지는 않는다.**

클라우드 `pull()` 도 같다. **로컬이 이긴다.**
실측으로 확인했다 — 같은 백업을 두 번 복구해도 장소가 늘지 않는다.

### 3. 구독은 **게이트 구조만**, 결제창은 흉내내지 않는다
`Subs.isPaid()` 는 지금 늘 false 다. "구독하기"를 누르면 아직 결제를 열지 않았다고 그대로 말한다.
차감 순서는 현장매니저 그대로 **쿠폰 → 월 한도 → 무료 지급분**.

☠️ **차감은 AI 호출이 성공한 뒤에 한다.** 실패한 호출까지 세면 사용자가 손해다.
☠️ **재설치 리셋 차단** — 무료 월 10회는 로그인 계정에 붙는다. 로그인 전에는 맛보기 3회뿐이다
(기기 기준이라 크게 주면 앱을 지웠다 깔면 되살아난다).

## 실측으로 잡은 버그 2건 (tools/smoke.js)

1. **요금제 창의 막다른 로그인 버튼** — Firebase 키가 없는데도 "로그인하기"가 떠 있었다.
   누르면 "아직 못 켠다"는 창이 또 떴다. 켤 수 없는 버튼은 내리고 이유를 위에 적도록 고쳤다.
2. (앞 라운드) 서비스워커가 첫 설치에도 새로고침을 걸어 앱이 두 번 뜨던 것.

`tools/smoke.js` 는 사람이 쓰는 순서대로 17개 지점을 실제로 눌러본다:
EXIF 파싱(37.5665, 126.9780 / 2026-08-20 12:34 정확히 읽음) → 장소에 반영 → 일괄 태그 →
맛보기 소진 후 잠김 → 백업 ZIP(파일명 ASCII 규칙 확인) → 장소 삭제 → 복구 왕복(사진↔장소 연결까지) →
두 번 복구해도 안 늘어남 → 지도 폴백 → 로그인 안내.

```
npm run check    # 코드가 어긋나지 않았나 (구문·로드목록·채널키·도메인단어·안전장치)
npm run smoke    # 사람이 쓰는 순서대로 실제로 되나 (playwright 필요)
```

`tools/check.js` 에 **안전장치 검사**를 더했다 — 게이트 호출, 성공 후 차감,
비파괴 복구, 공유 파일명 순번, `ov-lock` 이 코드에서 사라지면 실패로 잡는다.

## 다음에 채울 값 — `www/js/config.js`

| 값 | 필요한 곳 | 메모 |
|---|---|---|
| `FIREBASE` | 로그인·클라우드 백업·PC 링크 | **새 프로젝트를 새로 판다.** `www/site/post.html` 위쪽 `PROJECT`/`API_KEY` 에도 같은 값 |
| `PROXY_URL` | AI 글 생성 | 앱은 Firebase ID 토큰을 `Authorization: Bearer` 로 보낸다. **서버가 이걸 검사해야 한다** |
| `POST_BASE` | PC 링크 | `www/site/post.html` 을 올린 주소 |
| `KAKAO_REST_KEY` | 주변 장소 자동 채움 | ⬜ 쿼터·약관 확인 전 |
| `KAKAO_JS_KEY` | 지도 보기 | **REST 키와 다른 값.** 도메인 등록도 필요 |

키를 넣은 뒤 배포 순서:
```
firebase deploy --only firestore:rules,storage,functions,hosting
```

⚠️ `functions/deleteUserData` 를 배포하기 전에는 **계정 삭제가 Storage 파일을 지우지 못한다.**
Play 심사 전에 반드시 배포할 것.
