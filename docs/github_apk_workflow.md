# 깃허브를 이용한 테스트 APK 받기 — 작업 방식 정리 (2026-09-02)

찍고쓰다(Travel-post)에서 오늘 확립한 방식이며, 현장매니저(aircon-report)에도 그대로 적용할 수 있습니다.

## 전체 흐름

1. **Claude가 코드 수정 후, 사용자가 만들어준 PAT로 직접 push**
   - 저장소별로 fine-grained personal access token(해당 저장소만, Contents Read/write 권한)을 만들어 채팅에 붙여주시면, Claude가 이 토큰으로 `git push`를 직접 실행합니다.
   - Cowork 클라우드 세션은 일반적인 깃허브 push가 막혀 있어서, 이 PAT 방식이 유일한 우회로입니다.
   - 토큰은 사용한 뒤에도 지우지 않고 그대로 두시면 됩니다(Claude가 삭제를 권하지 않음).

2. **GitHub Actions가 자동으로 디버그 APK 빌드**
   - `.github/workflows/android-debug.yml`이 push를 감지해서 자동으로 빌드를 시작합니다.
   - 빌드된 APK는 고정된 릴리스 주소(예: `.../releases/download/test/파일명.apk`)에 `--clobber` 옵션으로 항상 덮어써집니다. 즉 주소는 매번 같고 내용만 바뀝니다.
   - 앱 서명키(`android/debug.keystore`)가 저장소에 고정으로 커밋되어 있어서, 매번 같은 키로 서명됩니다 — 이 덕분에 새 버전을 설치할 때 기존 앱을 지우지 않고 그대로 덮어쓰기 설치가 가능합니다(지우면 사진 등 저장된 데이터가 사라짐).

3. **빌드 완료 감지**
   - Claude가 릴리스 주소의 Last-Modified 헤더를 주기적으로 확인해서, 빌드가 끝나 파일이 갱신됐는지 확인합니다.

4. **보내기 전 반드시 버전 검증 (가장 중요)**
   - GitHub 릴리스의 CDN이 파일을 덮어쓴 직후 몇 분간 예전 파일을 돌려주는 경우가 있었습니다(2026-09-02 실제로 겪음 — v0.4.7을 요청했는데 안에 v0.4.6 내용이 들어있었음).
   - 그래서 Claude는 APK를 다운로드한 뒤 압축을 풀어서 안의 `www/js/version.js` 값이 실제로 원하는 버전과 같은지 직접 확인합니다. 다르면 다시 받아서, 맞을 때까지 반복한 뒤에만 사용자에게 보냅니다.

5. **파일명에 버전 표시**
   - 항상 같은 이름(예: `jjikgo-test.apk`)으로만 오면 어느 버전인지 구분이 안 되므로, 보낼 때 파일명에 버전을 넣습니다(예: `jjikgo-test-v0.4.10.apk`).

6. **APK는 요청할 때만 전송**
   - 빌드가 완성되어도 자동으로 보내지 않고, 사용자가 "apk 줘"라고 요청하면 그때 보냅니다.

## 현장매니저(aircon-report)에 적용하기

- 현장매니저 저장소에는 이미 같은 방식의 `.github/workflows/android-debug.yml`과 고정 서명키(`android/debug.keystore`)가 준비되어 있습니다. (사실 오늘 찍고쓰다에 이 구조를 만들 때 현장매니저 것을 참고해서 가져온 것이라, 원조가 현장매니저입니다.)
- 다음에 현장매니저 작업을 Cowork 클라우드 세션에서 하실 때는, **그 저장소 전용 PAT를 새로 하나 발급**해서 붙여주시면 위와 동일한 방식으로 바로 빌드·검증·전달이 가능합니다. (토큰은 저장소별로 따로 발급해야 합니다.)

## 참고 — 오늘 발견한 CSS 버그, 현장매니저는 해당 없음

찍고쓰다에서 하단 탭바에 글목록이 가려지던 버그는, `body`가 `height:100%`와 `box-sizing:border-box`를 함께 쓰면서 `body` 자신의 `padding-bottom`이 무효화되는 문제였습니다(`min-height`로 바꿔서 해결, v0.4.10).

현장매니저도 겉보기엔 같은 `html,body{height:100%}` + `border-box` 조합을 쓰고 있어 같은 위험이 있어 보였지만, 실제로 재현·측정해본 결과 문제가 없었습니다. 이유는 현장매니저의 하단 여백이 `body`가 아니라 `.main`이라는 자식 요소에 있고, 그 요소는 `min-height:100vh`를 쓰고 있어 문제가 되는 조합을 피해가기 때문입니다. 그래서 현장매니저는 이 건으로 따로 손댈 곳이 없습니다.
